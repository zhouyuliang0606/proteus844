# 任务书：把一张原理图做成 Proteus 工程

> 这份文件是**给别人（或子代理）用的完整任务说明**。
> 拿到它的人不需要任何额外背景，照着做即可。

## 目标

输入一张手画/扫描/截图的原图，输出一个**电气正确、能打开、画得能看**的 `.pdsprj`。

## 材料

| 东西 | 在哪 |
|---|---|
| 本工具包 | 就是本文件所在目录的上一级（`proteus844/`） |
| 要画的原图 | 调用方会告诉你路径 |
| Proteus 8.15 | 本机已装；另有 `proteus_*` 那组 GUI 自动化工具可用 |

## 硬性约束

1. **不要改本包里的源码** —— 那是交付物。要改就说明为什么，别偷偷改。
2. **产物写到临时目录**（如 `%TEMP%\work\`），不要写进包里。
3. **验收只认 Proteus 编译出的 SDF**。包里的 `verify-file`（文件级重建）是**自证的**，
   它只证明"画的和它声称的一致"，证明不了"画的和原图一致"。
4. **必须截图自己看**，并描述你看到什么，而不是"应该没问题"。
5. 卡住就如实说卡在哪、报什么错。允许只做部分结果，但要说清完成到哪。


## 快环 / 慢环（别把 1 秒的事做成 5 分钟）

| 环 | 用什么 | 耗时 | 查得出什么 |
|---|---|---|---|
| **快环** | python -m proteus844.cli assemble ... | **0.3~2 秒** | 布局尺寸、布线冲突、文件级验收、图纸自适应 |
| **慢环** | 开 Proteus + 编译 SDF + 截图 | 1~3 分钟 | 引擎级真值、渲染观感 |

**迭代只在快环里做。** 改布局、调间距、修布线，全用 ssemble 或 plan.check + erify_file，
**不要每改一次就开 Proteus 截图**。开 Proteus 只做两件事：

1. 最后出一次 SDF 做权威验收
2. 最后看一次渲染，确认观感

截图也要省着用：**裁局部放大**看关键区域，不要整屏读大图。

## 步骤

```bash
# 1) 自检（10 项，约 12 秒）。不通过就别往下走。
python -m proteus844.selftest

# 2) 读作业手册（比 README 详细得多，含所有已知坑）
#    skill/SKILL.md
```

然后按 `skill/SKILL.md` 走。要点：

- **先看 donor 里有什么**：`python -m proteus844.cli donors` 和
  `python -m proteus844.symbol_table donors/base.pdsprj`。
  donor 里没有的器件画不出来 —— `base.pdsprj` 最全（7400/7410/7404/RES/LED/LOGICSTATE）。
- **识别**：图放大 6~8 倍逐块看，用 `cli seg` / `cli junc` / `pin_hints` 辅助。
  确认每个器件的型号和每根线的两端。跨符号族的像素→格换算不可靠（SKILL §6 有说明）。
- **生成**：优先 `build_from_topology`（只给拓扑，工具自己布局布线）；
  要精确控制就自己给坐标，再 `plan_route` → `build`。
- **验证**：在 Proteus 里「工具 → 编译网络表」导出 SDF，
  用 `python -m proteus844.verify.netdiff <意图网表> <SDF>` 逐条比。
- **看**：截图，检查器件有没有重叠、线有没有斜的/绕远路、整块有没有越出页框。

## 图纸坐标这件事（最容易翻车）

**Proteus 的页框以中心为原点**（x ∈ ±W/2，y ∈ ±H/2）。
把电路放在正坐标会整块贴到右下角并越框。布局函数已自动居中，
但你**自己给坐标**时必须也居中。

## 报告格式

1. 最终文件路径 + 截图路径
2. SDF 里实际有哪些网络（逐条列出），和图上对不对
3. 用了哪些工具/命令（关键几条）
4. 卡住的地方（哪个命令、什么报错、你猜什么原因）
5. 观感：有没有超框、有没有绕远、能不能一眼看懂
6. 总耗时

**诚实第一。** 画得丑就说丑，错就说错，做不出来就说做不出来。
不要为了让结果好看而省略验证 —— 一张好看但错的图，比一张丑但对图危险得多。
